# Predicting Difficulty Rather Than Edge: Uncertainty-Aware Football Forecasting under Efficient Betting Markets

Code, data and result artifacts for the paper:

> **Predicting Difficulty Rather Than Edge: Uncertainty-Aware Football
> Forecasting under Efficient Betting Markets**

This repository reproduces every number and figure in the paper. All tables and
figures are generated by the scripts in `src/` from the raw match and odds files;
no result in the paper is hand-written.

## What the paper does

The study asks whether any learned method — statistical, tree-based, or a
domain-enhanced large language model — can beat the de-vigged closing odds of a
deep betting market, and what a forecasting system can usefully deliver when it
cannot:

1. **Outcome predictability is bounded by the market.** No learned method
   exceeds the accuracy of de-vigged closing odds (54.2%) on the held-out test
   period, and value-based betting loses money at every threshold.
2. **Difficulty, unlike the outcome, stays predictable.** An uncertainty index
   built for decisions separates reliable from unreliable matches before
   kickoff; abstaining on the uncertain ones improves risk-adjusted returns
   where confidence-, entropy- and market-confidence-based abstention do not.
3. **Reliability is the deliverable.** In an efficient market the quantity a
   decision-support system can realistically supply is the probability that its
   own prediction is wrong, not a claimed edge over the market.

## Data

- **Match results and closing odds:** football-data.co.uk (five major European
  leagues, 2019/20–2025/26).
- **Expected goals:** Understat, collected by `src/crawl_understat.py`.
- **Modelling table:** `data/processed/all_matches_featurized.csv` — 11,811
  matches. Splits are chronological: train 2019/20–2023/24, validation 2024/25,
  test 2025/26 (1,104 matches). Every feature is constructed from information
  available before kickoff.

## Headline numbers (test period, 1,104 matches)

| Quantity | Value |

| De-vigged closing odds, accuracy | 54.2% |
| De-vigged closing odds, log loss | 0.967 |

| Value betting on model confidence | negative at every threshold |

## Reproducing

```bash
pip install -r requirements.txt
```

Then either run `refresh_all.cmd` (Windows) or follow the ordered steps in
`docs/REFRESH_CHECKLIST.md`. Both regenerate the processed data, all result
artifacts in `results/`, and the figures and tables used by the manuscript.
The pipeline is deterministic: repeated runs on unchanged inputs reproduce the
numeric result fields.

Model pickles and raw logs are intentionally not committed — they are
regenerated by the scripts. See `.gitignore`.

## A note on the manuscript file

`paper/main.tex` is a single self-contained LaTeX file: the tables and the
bibliography are inline, so no additional `.bib` or per-table files are needed.
Earlier states of the repository used a split layout (`paper/sections/`,
`paper/tables/`); those files were merged into `main.tex` when the manuscript was
revised, and remain available in the tags below if needed.
